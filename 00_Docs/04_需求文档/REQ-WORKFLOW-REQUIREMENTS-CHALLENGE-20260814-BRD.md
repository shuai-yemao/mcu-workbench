# BRD：独立需求质疑与双方案选择 Skill

## 项目背景与目标

当前流程能收集 RCP 并进行代码前审查，但缺少一个明确质疑需求目的、工程可行性并让用户比较候选方案的决策阶段。目标是在进入 Review Gate 前增加独立 Challenge Skill，降低未经目的审查或证据不足的需求直接进入实施规划的风险。

## 价值与约束

- 让需求目的、可行性和验收条件在实施前显式化；
- 保留两个真实方案及其取舍，避免单一路径过早固化；
- 用户拥有最终选择权；
- 不扩大 Router、Review Gate 和 Integration Plan 的职责；
- 不以文档或主机证据替代目标运行/实物证据。

## 成功标准

初步 RCP 能进入 Challenge；Challenge 产出两个可比较方案；用户选择被回填 RCP；未选择时不会越过 Review Gate；目录、文档和自动化测试保持一致。
