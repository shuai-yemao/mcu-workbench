# GPIO 输出外设生成与审查检查表

适用于 LED、继电器、使能脚等“逻辑状态 → GPIO 电平”的 BSP 切片；它们不需要为了套用通用器件模板而虚构寄存器协议、MCU Ops、OSAL 线程或 ISR 事件。

## 板级绑定证据

- 生成前读取目标工程的公开 Core GPIO 头和板级原理图/Pin 配置，记录 GPIO 实例、引脚、输出模式、初始电平及有效电平。
- 对 APP 暴露逻辑 `set(on)`；Driver 或注入的板级 Ops 必须把逻辑状态转换为实际高/低电平。不得把未说明极性的 `bool on` 直接当作物理电平。
- Port 必须注入实际的 Core GPIO 对象或有明确所有权的上下文。仅声明裸 `extern` 回调或传入无说明的 `NULL` context 时，只能作为预览，并在 manifest 标记 `UNRESOLVED_GPIO_BINDING`。
- GPIO 模式配置由 Core 后端完成；Driver 只使用已经注入的语义化读写 Ops，不直接调用 HAL/LL。

## 生命周期、错误与并发

- 即使同步短操作不需要工作线程，仍要定义 `init`、`set`、`deinit` 的前置条件、幂等性和失败后状态；每次初始化尝试前清除或进入明确的非 ready 状态，成功后才恢复 ready。
- 从 Core GPIO 到 Driver、Handle、Wrapper 的错误码必须保留可诊断语义；不得无理由逐层压缩为单一 `-1`。
- Port 按阶段装配并在任一阶段失败时回滚已注册的 Ops 和已创建资源。Wrapper 重注册与 APP 调用的并发关系必须明确：默认仅允许启动期注册；若支持运行期重注册，必须保证函数表替换原子且不破坏正在执行的调用。

## 验证与生成质量

- 生产 Port 与 Fake Port 注册同形 `p_context + pf_*` 表；Fake GPIO 至少覆盖高/低有效电平、初始化失败、写失败、失败后重试和重复初始化。
- 完整注释 Profile 声明必须与生成物一致：每个头/源文件具备所需文件元数据、分区、函数参数/返回/ISR 信息，以及 GPIO 状态、极性、上下文和回滚原因说明。
- 此类切片的 host/Fake 测试只证明调用链和错误路径；目标板日志或 GPIO 波形才证明实际电平和板级连接。
