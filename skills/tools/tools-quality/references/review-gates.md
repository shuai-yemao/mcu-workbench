# 项目代码审查门禁

本门禁适用于 AI 生成、代码生成器产物、人工新增、人工修改和已有代码重审；
“生成代码”仅表示代码来源，不是单独的架构或质量规则。

## 报告类别

| 类别 | 依据 | 示例 |
| --- | --- | --- |
| 风格 | 已确认的项目 profile | 缩进、括号、命名或注释不一致 |
| 功能 | 接口契约、调用链和测试 | 错误码遗漏、资源所有权错误、边界遗漏 |
| 安全 | 上下文、数据手册和并发证据 | ISR 阻塞、DMA 缓冲区不安全、数组越界 |

## 检查顺序

1. 确认审查范围、代码来源、profile（按 [style-profile 编码规范](style-profile.md) 的硬性约束）和可复现构建/测试命令；
2. 先检查编译、接口、错误路径和资源所有权；
3. 再检查 ISR/DMA/并发、数组边界及硬件约束；
4. 最后报告 profile 偏差，并注明其来源；
5. 按 style-profile 硬性约束核对：当前分层文件命名、`g_/s_/p_/pf_` 变量前缀、公开函数 Doxygen（`@brief`/`@param`/`@retval`，按需使用 `@note`/`@warning`）、左对齐-填充-右对齐注释与 80 列硬限制；用户或项目明确采用其他约定时以该约定优先。
