# 嵌入式验证交接

## 变更范围到工具链的交接

Git 只记录和组织变更；它不替代构建、静态检查、主机测试、目标板运行、RTT/串口观测或硬件验收。根据已确认的变更范围，在证据报告中建议以下交接：

| 变更范围 | 建议交接 | 需要说明 |
| --- | --- | --- |
| 源码、接口、注释、测试或架构规则 | `tools-quality` | 静态检查、审查、主机测试及其证据 |
| CMake、Keil、IAR、ESP-IDF、PlatformIO、工具链或构建产物 | `tools-build` | 配置、实际命令、产物路径和构建结果 |
| 版本、标签、固件包、OTA、发布记录 | `tools-release` | 版本兼容、签名/包、回滚与发布验证 |

## 证据边界

`tools-git` 只能报告 Git 差异、提交、分支、标签和用户提供的验证结果。它不替代 `tools-quality`、`tools-build` 或 `tools-release`，也不能把“已暂存”“已提交”或“Git 命令成功”描述成质量、构建、烧录或板级验证通过。

报告中按事实区分：未运行、已运行但失败、已运行且通过、验证待补。若代码涉及硬件行为，目标板、RTT、串口、逻辑分析仪或 DWT 的结论必须由相应工具链和实测证据支持。
