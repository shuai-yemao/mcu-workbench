# Git 安全操作契约

## 默认只读与范围保护

先检查仓库根、worktree、分支、上游和 `git status`，再解释差异。混合工作区中的未关联改动属于用户资产：记录其状态，但不暂存、恢复、丢弃、移动或覆盖。

暂存必须使用明确文件路径。禁止使用 `git add -A`、`git add .` 或未核对范围的通配符；先展示拟暂存文件，再等待确认。对 CRLF 或格式化噪声，先区分语义差异与空白差异，不能把噪声当作功能变更。

## 写操作确认

创建/切换分支、创建/删除 worktree、暂存、提交、合并、变基、标签、stash、fetch、pull、push、远端配置变更都属于写操作。每一项都必须在执行前取得明确确认；确认一个动作不等于确认后续动作。

确认信息必须说明：仓库根和 worktree、目标分支/引用、精确文件或提交范围、拟执行命令、预期影响及是否可恢复。

## 破坏性操作

`git reset`、`git clean`、`git restore`、`git branch -D`、`git tag -d`、`git push --force`、历史改写及会覆盖本地变更的同步，先输出精确目标、将失去或改写的内容、恢复方案和预览结果，再逐项确认。

`git clean` 必须先使用 dry-run 并限定已确认路径；不得对仓库根执行无目标的清理。历史改写或强推必须再次确认目标远端和分支，且不得以“普通同步”名义执行。

## 失败、冲突与恢复

命令失败时停止后续写操作，保留当前状态并报告第一处失败。合并或变基冲突时先列出冲突文件、当前 Git 操作和可选路径（继续、放弃、手动解决）；未得到确认不执行 `--continue`、`--abort` 或恢复命令。

仅在已确认的仓库和 worktree 内操作。发现嵌套仓库、submodule、LFS、受保护分支或远端策略不明时，报告边界并请求方向。
