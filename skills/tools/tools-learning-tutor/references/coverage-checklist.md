# 笔记覆盖与查漏补缺

生成草稿后逐项检查，不批量跳过：

- [ ] 每个 Obsidian 栏目都有对应的已确认回答、代码证据或明确的"未验证"标记；
- [ ] 引言在其余栏目完成后生成，且总结只包含已确认的工程结论，不是对话逐字稿；
- [ ] 机制说明覆盖触发源、参与者、选择条件、数据/上下文、结果消费者和边界；
- [ ] Q&A 的基础、进阶、困难题分别覆盖用法、易混边界和迁移/取舍；

- [ ] 每个重要 `typedef struct` 及字段；
- [ ] 每个公开 API、函数指针和回调；
- [ ] 每个配置宏、默认值、可选值和编译条件；
- [ ] 错误码、异常路径、超时和恢复策略；
- [ ] 初始化顺序、启动顺序和去初始化逆序；
- [ ] 缓冲区、句柄、队列、任务和资源所有权；
- [ ] ISR/任务/线程上下文限制；
- [ ] 与其他模块的调用关系和边界；
- [ ] 模块职责、依赖方向和可替换边界是否清晰；
- [ ] 数据所有权、控制流、生命周期和关键不变量是否解释；
- [ ] 至少比较过一个替代方案，并说明当前方案的取舍依据；
- [ ] 架构结论是否区分代码现状、目标设计、推断和未验证项；
- [ ] 代码与旧笔记的过期项；
- [ ] 仍未验证的硬件、版本和数据手册事实。

## 项目驱动学习覆盖

- [ ] 当前学习目标的深度层级（L1/L2/L3）已记录，且 tutor 推进深度与该层级一致；
- [ ] L1 阶段只覆盖"最小必要学习清单"的 7 项，未越界引入 L2 内容；
- [ ] 最小实验已设计并执行，实验结果与项目集成分开记录；
- [ ] 三问检查（为什么能工作/关键参数/需求改变改哪里）三项均有答案，否则标记为"待补理解"；
- [ ] 非阻塞知识已记入 Learning Backlog，未中断当前任务去展开学习；
- [ ] Learning Backlog 中出现次数 >= 2 的知识点已提示用户可提升到 L2；
- [ ] 项目完成度与知识掌握度分开标注，未因知识未完全掌握而标记项目未完成；
- [ ] 停止条件已检查（问题清楚/有方案/可实验/可验证/知道排查路径）。

## 表达与授课覆盖

- [ ] 技术文档能让同组工程师知道如何接入、修改和验证；
- [ ] 技术博客先说明问题和背景，再解释机制，不堆砌 API 名称；
- [ ] 教学讲解有前置知识、递进顺序、示例和理解检查问题；
- [ ] 三种输出均让用户先独立表达，但 Obsidian 只沉淀已确认理解、判断依据和证据，不逐字转录用户原话或 AI 批改；
- [ ] 输出明确适用范围、读者对象和下一步练习。
- [ ] 实际操作对应当前工程的入口、配置、构建/日志/板级观察点和失败分支；
- [ ] 每张核心机制图同时提供真实 Mermaid、SVG 源码和无外部依赖的 React 组件源码，三者引用同一工程证据。

发现遗漏时一次只展示一项：

```text
[1/N] `symbol` 在草稿中缺少 `relative/path.c:line` 的字段说明。[补充? y/n]
```

用户选择补充后更新草稿，再继续下一项；选择跳过则记录为未覆盖项。
