MCU WORKBENCH · 嵌入式工作台架构

从需求约束到分层实现、目标板验证与最终质量门禁的宿主工作流

工作流门禁

  • • Router 生成可审计 RCP
  • • Challenge 补齐目的与可行性
  • • Review Gate 决定放行或阻塞
  • • Spec → Plan → Task → Verify

固件分层

  • • App 只依赖 Service 公开 API
  • • Service 承载业务策略与状态
  • • Platform 只定义能力契约
  • • Impl 绑定机制，Vendor 保留底座

验证出口

  • • 静态、主机、构建、目标板分层
  • • 目标板证据来自串口 / RTT / DWT
  • • 质量整改仅限格式与必要注释
  • • 不把静态结果写成硬件验证
